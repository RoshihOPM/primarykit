# PrimaryKit

Персональный конструктор backend-проектов на **Django + Django REST Framework**.

## Цель

Использовать проверенную базу Django и каталог готовых приложений для быстрого старта независимых проектов: CRM, маркетплейсов, интернет-магазинов и внутренних систем.

**Модель переиспользования — копирование исходного кода**, а не общий runtime или зависимость от опубликованных Python-пакетов.

## Принципы

- **Core** — обычный Django-проект: конфигурация, API, logging, healthchecks, Docker и тестирование.
- **Apps** — самодостаточные функциональные модули с моделями, API endpoints, serializers, services, permissions и тестами.
- В новый репозиторий проекта переносятся Core и **только выбранные** Apps.
- Исходный каталог модулей не содержит прикладных миграций. Для каждого нового проекта начальные миграции создаются локально и **обязательно коммитятся** в его Git.
- После создания проект независим от PrimaryKit. Обновления модулей переносятся осознанно и с учётом существующих миграций.
- Без привязки универсальных Apps к бизнес-моделям конкретного заказчика.
- Не запускаем Redis, Celery, RabbitMQ и другие сервисы, пока они не нужны проекту.

## Планируемые модули

| Модуль | Назначение |
| --- | --- |
| `users` | Регистрация, авторизация, профили, управление пользователями |
| `rbac` | Роли и разрешения |
| `storage` | Работа с файлами и S3-совместимыми хранилищами |
| `audit` | Журнал действий и изменений |
| `notifications` | Каналы и доставка уведомлений |
| `wallets` | Балансы, операции, идемпотентность |
| `chats` | Диалоги и сообщения |
| `payments` | Платёжные интеграции |
| `promocodes` | Промокоды и ограничения применения |

## Статус

**Design / bootstrap.** Исходный код Core и модулей ещё не реализован. До генерации первого проекта необходимо зафиксировать контракты модулей и тесты совместимости.

Архитектурные решения, scope и этапы реализации будут размещены в `docs/`.
