# Feature Flags — локальные переключатели релизов

`apps/feature_flags` — опциональный переносимый модуль. Нет таблиц, Redis, фонового worker, внешнего API или runtime-зависимости от репозитория PrimaryKit.

## Контракт

В `config/settings/local.py` или в настройках собственного клиента задайте словарь:

```python
FEATURE_FLAGS = {
    "new_checkout": False,
    "experimental_search": True,
}
```

Используйте `from apps.feature_flags.services import is_enabled`, затем `is_enabled("new_checkout")`. Отсутствующий флаг возвращает `False`. Допустимые имена — lowercase snake_case длиной 1–64 символа; значения строго `bool`. Некорректная конфигурация вызывает `ImproperlyConfigured` при обращении.

Флаги принадлежат **каждому клиентскому проекту**. Изменения следует доставлять через собственный Git/CI/deploy. Нет удалённого управления, процентного rollout, пользовательских сегментов или автоматического обновления конфигурации — это сделано намеренно, чтобы избежать зависимостей и непредсказуемых решений.

**Безопасность:** флаги не предоставляют права. Не используйте их вместо permissions, tenant scoping, проверки платежей или финансовых ограничений. Решения о доступе всегда проверяются независимо от состояния флага.

## Проверки

`uv run pytest apps/feature_flags/tests` и генерация из каталога с `--apps feature_flags`. После генерации клиент может изменить реализацию; обновления конструктора не применяются автоматически.
